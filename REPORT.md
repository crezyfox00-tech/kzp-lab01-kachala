# ЗВІТ ПРО ВИКОНАНУ РОБОТУ (Лабораторна робота № 3)

### 1. Тема, номер і варіант
* **Тема:** Поліморфізм та ієрархія класів у Java.
* **Номер роботи:** Лабораторна робота № 3.
* **Варіант:** Варіант 12.
* **Предметна область:** Розсадник рослин.
* **Операційна система:** Windows (PowerShell, Maven).

### 2. Мета роботи
Досягнуто стану успішного проєктування та реалізації поліморфної ієрархії класів (`Plant`, `Tree`, `Flower`), впровадження абстрактного базового класу, перевірки інваріантів, забезпечення роботи статичного аналізу (SpotBugs) і юніт-тестів із повним збереженням зворотної сумісності з попередніми лабораторними роботами.

### 3. Стан до і після цієї роботи
* **До роботи:** Існував єдиний плоский клас `Plant` із базовими полями, а також контролер `NurseryController` для зчитування даних і формування звітів із CSV-файлів.
* **Після роботи:** Створено повноцінну ієрархію: абстрактний базовий клас `Plant` та конкретні підтипи `Tree` і `Flower`. Логіка обробки розширена за допомогою поліморфізму, додано валідацію вхідних даних та забезпечено проходження всіх модульних тестів і перевірок SpotBugs.

### 4. Базовий тип
* **Спільні поля:** `species` (вид), `name` (назва), `kind` (категорія), `heightCm` (висота у см), `price` (ціна), `wateringDays` (дні поливу).
* **Інваріанти:** Назва та вид не можуть бути порожніми; числові показники (висота, ціна, дні поливу) мають бути додатними.
* **Абстрактні методи:** Поліморфний метод `careRequirement()` для оцінки потреби в догляді.

### 5. Підтипи
* **`Tree` (Дерево):** Містить додаткове унікальне поле `trunkDiameterCm` (діаметр стовбура). Поліморфний метод `careRequirement()` реалізований через розрахунок на основі діаметра стовбура.
* **`Flower` (Квітка):** Містить додаткове унікальне поле `bloomingMonths` (кількість місяців цвітіння). Поліморфний метод `careRequirement()` обчислюється на основі періоду цвітіння.

### 6. enum
* Використовується перерахування **`PlantKind`** для класифікації категорії рослин (наприклад, `TREE`, `FLOWER`), що дозволяє безпечно розрізняти типи об'єктів у бізнес-логіці та звітах.

### 7. equals і hashCode
* Критерій рівності базується на унікальній назві рослини (`name`) та типі класу. Перевірка коректно працює під час збереження та пошуку об'єктів у колекціях Java.

### 8. Поліморфізм
* У контролерах та звітах спільний базовий тип `Plant` обробляє масиви та колекції підтипів (`Tree`, `Flower`) через виклик абстрактного методу `careRequirement()` без використання жорстких перевірок умов типу (`instanceof` чи `if` за типом).

### 9. Тестування
* Додано нові модульні тести у `PlantTest` для перевірки створення та валідації `Tree` і `Flower`. 
* Збережено сумісність зі старими тестами (`MainTest`, `NurseryController`), які перевіряють коректність побудови звіту та обробку винятків для некоректних рядків CSV.

### 10. Інфраструктура
* Використано систему збирання **Maven**. 
* Команди для перевірки:
  * Очищення та тести: `.\mvnw.cmd clean test`
  * Повна перевірка з аналізатором і пакетом: `.\mvnw.cmd clean verify package`
* Успішно пройдено етапи компіляції, юніт-тестування (Surefire) та статичного аналізу коду (SpotBugs).

### 11. GitHub Issues i Pull Request

### 12. Порівняння поведінки
* Доведено повну сумісність нового звіту зі структурами попередньої лабораторної роботи: збережено формати виведення даних, сумісність із класом `HeightWatering` та фабричним методом `fromCsv()`.

### 15. Висновки

Забезпечено високу якість коду, проходження статичного аналізу SpotBugs та повну сумісність із попередніми функціональними вимогами. Отримані навички стануть основою для наступних лабораторних робіт.
