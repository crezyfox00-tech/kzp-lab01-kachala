# ЗВІТ ПРО ВИКОНАНУ РОБОТУ (Лабораторна робота № 3)

### 1. Тема, номер і варіант
* **Тема:** Поліморфна ієрархія класів та юніт-тестування у Java-проєкті.
* **Номер роботи:** Лабораторна робота № 3.
* **Варіант:** Варіант 12.
* **Предметна область:** Розсадник рослин.
* **Операційна система:** Windows (PowerShell, Maven).

### 2. Мета роботи
Створити поліморфну ієрархію класів для предметної області «Розсадник рослин», реалізувати базовий клас, підтипи, перерахування (`enum`), забезпечити коректність контрактів (`equals`, `hashCode`, `toString`), покрити код юніт-тестами (JUnit 5) та перевірити проєкт за допомогою статичного аналізатора SpotBugs.

### 3. Стан до і після цієї роботи
* **До роботи:** Проєкт містив початкову структуру або потребував створення предметної моделі розсадника рослин з нуля.
* **Після роботи:** Створено повноцінну об'єктно-орієнтовану ієрархію з абстрактним базовим класом, конкретними підтипами, перерахуванням та захистом інваріантів.

### 4. Базовий тип
* Абстрактний базовий клас `Plant` містить спільні поля (`species`, `name`, `price`, `heightCm`, `wateringDays`), інваріанти валідації вхідних даних, а також абстрактні або загальні методи для роботи з об'єктами.

### 5. Підтипи
* Класи `Tree` та `Flower` успадковують `Plant`, реалізують унікальні специфічні поля (наприклад, тривалість цвітіння чи діаметр стовбура) та забезпечують поліморфну поведінку.

### 6. enum
* Використано перерахування `PlantKind` для визначення категорій рослин у розсаднику, що гарантує типобезпеку та чіткий розподіл за типами.

### 7. equals і hashCode
* Перевизначено методи `equals` та `hashCode` на основі ключових бізнес-полів, що дозволяє коректно порівнювати екземпляри рослин та використовувати їх у колекціях.

### 8. Поліморфізм
* Усі колекції та алгоритми оперують спільним базовим типом `Plant`, викликаючи методи підтипів у динамічному режимі без використання розгалужень за типом (`instanceof` чи перевірки `if`).

### 9. Тестування
* Розроблено комплекс модульних тестів (`PlantTest`, `MainTest`), які покривають позитивні сценарії, граничні значення та роботу з винятками при не валідних даних.

### 10. Інфраструктура
* Налаштовано збирання через **Maven** (`./mvnw.cmd`). Успішно виконуються команди тестування, перевірки статичним аналізатором SpotBugs та пакування проєкту у виконуваний `JAR`.

### 11. GitHub Issues і Pull Request
* Процес розробки супроводжувався роботою з гілками, комітами та оформленням історії змін у репозиторії.

### 12. Порівняння поведінки
* Доведено сумісність поточної реалізації з архітектурними вимогами предметної області та коректність успадкування.

### 13. Висновки
* Успішно спроєктовано та реалізовано поліморфну ієрархію класів для розсадника рослин (Варіант 12). Усі тести проходять успішно, код готовий до подальшого розвитку.
