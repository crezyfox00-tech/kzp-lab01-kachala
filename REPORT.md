# ЗВІТ ПРО ВИКОНАНУ РОБОТУ (Лабораторна робота № 5)

### 1. Тема, номер і варіант
* **Тема:** Параметризоване сховище, винятки й CSV-експорт у Java-проєкті.
* **Номер роботи:** Лабораторна робота № 5.
* **Варіант:** Варіант 12[cite: 19].
* **Предметна область:** Розсадник рослин[cite: 19].
* **Операційна система:** Windows (PowerShell, Maven).

### 2. Мета роботи
Завершити Java-застосунок наскрізного продукту: замінити пряме зберігання даних у списку на параметризоване сховище `Repository<T>`, додати власний виняток із ланцюгом причин, описати CSV-стовпці анотацією `@CsvColumn` та реалізувати універсальний експортер, який читає метадані рефлексією. Дані записуються і читаються через `Path` та `Files` із явним `UTF-8`[cite: 10].

### 3. Стан до і після цієї роботи
* **До роботи:** Дані зберігалися у звичайному полі-списку в пам'яті без підтримки збереження у зовнішні файли формату CSV та рефлексивного експорту[cite: 10].
* **Після роботи:** Додано типобезпечне сховище `Repository<T>`, кастомний виняток `DataStorageException`, рефлексивний експортер та документний парсер із підтримкою екранування і збереження в CSV-файл[cite: 10, 14, 16].

### 4. Repository<T>
* Реалізовано узагальнений клас `Repository<T>` без використання `raw types`[cite: 12].
* Методи: `add(T item)` (додавання з перевіркою на `null`), `all()` (повертає незмінний знімок через `List.copyOf`), та `find(Predicate<? super T> condition)` для гнучкого пошуку за умовою[cite: 12].

### 5. Модель даних
* Предметний клас `PlantRecord` містить поля: `species` (вид, `String`), `ageYears` (вік, `int`), `heightCm` (висота, `double`), `price` (ціна, `double`), `wateringDays` (полив, `int`)[cite: 19].
* Реалізовано перевірки валідності в конструкторі, а також методи `equals` та `hashCode` за всіма ключовими полями (ключ round-trip: `species + ageYears`)[cite: 19].

### 6. @CsvColumn
* Створено власну анотацію `@CsvColumn` із `@Retention(RetentionPolicy.RUNTIME)` та `@Target(ElementType.FIELD)`[cite: 12].
* Одноэлементний параметр `String value()` задає назву заголовка стовпця у CSV[cite: 11, 12].

### 7. Рефлексивний експортер
* За допомогою рефлексії (`getDeclaredFields`) експортер знаходить усі анотовані поля, сортує їх за іменем для забезпечення детермінованого порядку заголовків, перевіряє доступ через `trySetAccessible()` та формує CSV-рядок[cite: 13, 14].

### 8. Формат CSV
* Заголовок формується з українських назв анотацій (`вид`, `вік`, `висота`, `ціна`, `полив`)[cite: 19].
* Використовується кодування `StandardCharsets.UTF_8`[cite: 10, 14]. Поля з комами, лапками чи перенесенням рядків автоматично екрануються подвійними лапками[cite: 13, 14].

### 9. Імпорт і round-trip
* Документний парсер (`CsvParser`) розбирає текст із урахуванням лапок і багаторядкових полів[cite: 13, 16].
* Метод відновлення об'єктів та тест `round-trip` доводять повну еквівалентність початкового та відновленого списків через `equals`[cite: 14, 15].

### 10. Помилки
| Рівень помилки | Приклад / Причина | Реакція програми |
| :--- | :--- | :--- |
| **Модель** | Некоректні дані рослини | `IllegalArgumentException` у конструкторі |
| **Формат** | Хибна кількість полів / помилка парсингу | `DataStorageException` |
| **Файл** | Немає доступу до теки / помилка IO | `DataStorageException` із `IOException` як `cause`[cite: 15] |

### 11. Тестування
* Додано клас модульних тестів `StorageTest`, який перевіряє роботу `Repository<T>`, екранування ком, обробку помилок файлової системи та успішне проходження `round-trip` для `PlantRecord`[cite: 14, 15, 20]. Усі попередні тести проєкту також проходять успішно[cite: 18].

### 12. Інфраструктура
* Використано систему збирання **Maven** (`./mvnw.cmd`)[cite: 15]. 
* Команди `clean test`, `verify` (зі статичним аналізатором SpotBugs) та `package` (створення виконуваного `JAR` через maven-shade-plugin) виконуються успішно[cite: 15].
* Налаштовано CI на GitHub Actions для Ubuntu, Windows та macOS з публікацією `JAR` як артефакту[cite: 15, 18, 41].

### 13. GitHub Issues і Pull Request
* Процес розробки супроводжувався створенням окремої гілки `lab5`, комітами та оформленням Pull Request із прикладом CSV і результатами round-trip[cite: 16, 18, 21].

### 14. Порівняння стану
* Доведено збереження всієї попередньої функціональності попередніх лабораторій (поліморфізм, Stream API) та розширення застосунку можливістю стійкого збереження у файлову систему[cite: 10, 18].

### 15. Висновки
* Успішно завершено розробку наскрізного Java-проєкту: створено параметризоване сховище `Repository<T>`, реалізовано універсальний рефлексивний CSV-експортер з екрануванням, забезпечено роботу з UTF-8 та створено надійні тести. Отриманий CSV-файл є повністю стандартизованим і готовим до використання як вхідні дані для наступного програмного блоку[cite: 10, 23].
